How does the catalog discover its content?

The catalog server needs to know about REST endpoints, commands, events, and Kafka/pg-boss channels. How should it get that information?

A

Static manifest file (catalog.yaml / catalog.ts)

Each e2e app ships a hand-written or code-generated manifest that lists all HTTP routes, commands, events, and async channels with their schemas. The catalog server just reads this file at startup.

funds/catalog.ts
export default {
  http: [
    { method: "POST", path: "/api/funds/deposit",
      command: "DepositFunds", schema: DepositFundsSchema },
  ],
  async: [
    { channel: "kafka:funds.outbox",
      message: "FundsChanged", direction: "publish" },
  ]
}
B

Runtime self-registration via catalog SDK

Each server calls a catalog.register() function when it starts up. The catalog server aggregates registrations over HTTP. Servers declare themselves — catalog doesn't need to know about them ahead of time.

server.ts — startup
await catalog.register({
  service: "funds-main",
  baseUrl: "http://localhost:3014",
  routes: [...],
  asyncChannels: [...],
})
C

Crawl OpenAPI + static async spec

Each server exposes a GET /openapi.json endpoint (auto-generated from routes). The catalog server crawls all known services at startup to fetch their specs. Async channels are declared in a separate static AsyncAPI YAML.

Catalog startup flow
1. Fetch localhost:3014/openapi.json → REST spec
2. Fetch localhost:3013/openapi.json → REST spec
3. Load asyncapi.yaml → async channels
4. Merge → render UI
