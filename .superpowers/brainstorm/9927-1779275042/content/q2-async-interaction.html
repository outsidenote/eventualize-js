How interactive should the async side be?

The funds app has two async flows: Kafka → RiskAssessment (CDC via Debezium) and pg-boss → AccountLeaderboard (outbox trigger). For REST endpoints, "Try it out" is obvious. For async channels — what level of interactivity do you need?

A

Document-only (read-only catalog)

Show each async channel with its schema, payload examples, and flow diagram. No ability to publish/trigger from the UI. REST endpoints still have "Try it out".

[ No send button — documentation only ]
B

Publish test messages to Kafka / pg-boss

From the catalog UI you can fill a JSON form and publish a test message to a Kafka topic or enqueue a pg-boss job directly. Great for testing consumers in isolation without having to hit the REST API first.

Try it — Kafka: funds.outbox → RiskConsumer
C

Live event stream viewer

The catalog tails Kafka topics and outbox in real time, showing a live feed of events as they flow. Combine with REST "Try it out" — deposit funds, then watch the event appear in the stream below. Ideal for demos and E2E debugging.

You can also pick multiple — e.g. B+C (publish + live stream).
